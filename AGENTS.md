# AGENTS.md

Guidance for coding agents (Claude Code, Codex, opencode…) working in this repository. **Keep this file current**: when you add a crate, a command, a convention or a gotcha, update it in the same change.

## What this is

xherd: a daemon (Rust) that runs, watches and steers many coding agents, each in its own git worktree and tmux session, with approval gates. Read before changing behaviour:

- `doc/internal/spec.md` — what (requirements `R-xxx`)
- `doc/internal/design.md` — how (crates, architecture, milestones §18, decisions §19)
- `doc/reference/xap.md` — agent protocol (`xherd hook|report|gate|task|commit …`)
- The final docs, by reader (index `doc/README.md`; layout and rules in `doc/dev/development.md` → Writing docs): `doc/user/` (`getting-started.md` for published releases, `guide.md` using xherd, `docker.md`, `security.md`), `doc/reference/` (`cli.md`, `configuration.md`, `http-api.md`, `xap.md`), `doc/extend/` (`plugins.md`, `flow-packs.md`, `integrate-your-sdd.md`), `doc/dev/` (`from-source.md`, `development.md`, `architecture.md`). They replace spec/design when those go; **update them in the same change as the behaviour they describe** (a new CLI flag → `cli.md`, a config key → `configuration.md`, a route → `http-api.md`, a user-visible feature → `guide.md`). `README.md` at the root is the presentation page.
- `ROADMAP.md` — what is left, by theme (the milestone checklist in `doc/internal/design.md` §18 stays the source of truth; update both)

Decisions in `doc/internal/design.md` §19 are settled; do not re-open them in code. Cite requirement ids (`R-009`) in doc comments where code implements one.

`maxSessionMinutes` (R-1206, config, 0 = off, read at daemon start): `TickKind::SessionLimit` (each minute) ends a live agent's session and pauses it once `Agent.session_since` (set at launch and at each fresh session) is older; it asks for a handoff first, like the Pause button (below).

Pause with a handoff (R-026): `Actor::begin_pause` (Pause button, `xherd pause`, `SessionLimit`) sends the pack's `handoff` command to a live flow agent that is running, idle or waiting, and sets `Agent.pause_requested_at` (UI: "Pausing…"); the session ends and the agent is `paused` at the first stop after `handoff written` (`handoff_at >= pause_requested_at`; earlier stops, auto-approval and `after_ship` are skipped meanwhile), or after `pauseTimeoutSec` (`ActorSettings::pause_timeout`, checked on the 3 s `ScreenScan` tick; notified as "paused without a handoff note"). A blocked agent, flow `none`, a pack without the command or a send that fails pause at once. Cancel and any end of the session clear the request. Resume after a handoff with `freshSessions` on starts a fresh session with the pack's `resume` command instead of `claude --resume` (`prepare_resume` uses up `handoff_at`); `.xherd/HANDOFF.md` stays in place and is read by `/xherd:resume` again on a later resume. `xherd docker update` waits until the agents it paused are `paused`. The budget pause (`budget-exhausted`) deliberately does not ask for a handoff: it exists to stop spending. Kill switch (R-032): `POST /agents/pause-all` / `xherd pause --all` / the Herd's "Pause all" button run `UserAction::PauseNow` on every queued and live agent (queued first, so a freed slot starts nothing): the session ends at once, no handoff note, and a pause still waiting for one is cut short. A queued agent can be paused (`Trigger::Pause` accepts `Queued`; resume queues it again). This follows spec R-032 ("at once"), not the earlier design text "handoff requests in parallel", which was changed to match.

Token budgets (R-1205): `agentTokenBudget` / `dailyTokenBudget` (config, 0 = off, read at daemon start). After each stop `Actor::measure_usage` reads the session's transcript (`Resumer::transcript`, found through the runtime plugin's `data.terminal.resume`) in a spawned task; the runtime plugin declares how to read it (`data.terminal.usage`: `records` / `id` JSON pointers and a `fields` name per standard counter; `xherd_plugin::runtime::Usage::totals`; it needs `resume`, which locates the transcript), and xherd counts input + output + cache write (`Totals::budget_tokens`, not cache reads) for every runtime. For Claude Code the id is the message id, which the runtime repeats per content block, so the last line of an id counts. `Agent::record_usage` is cumulative per session (`tokens_base` + `tokens_session`), so a dropped measurement is caught up by the next; the day's total over all agents is in the `budgets` table (scope `all`, UTC day). 80 % notifies once per agent (`budget_warned`), 100 % pauses at that stop (`budget-exhausted`). A resumed session with a new id that copies old messages is counted again.

Review→fix loop (R-114/R-120): the review prompt turns must-fix findings into tasks with `source: review` (`Task.source`, parsed from `tasks.md`), they are implemented through `/xherd:next`, and the agent returns with `xherd stage enter review`; coming back to a review stage already visited from another stage is a round (`Agent.review_rounds`, counted in `xap::apply`). `Actor::review_hold` sets the review docs gate's `needs_human` while review tasks are open or rounds exceed `maxReviewLoops` (config, default 3, 0 = no limit, read at daemon start). `review.md` findings are Markdown, `### F01: title` plus `- severity:` (minor, major, blocker), `- location:`, `- fixed: T05, T06`, `- left:` (`xherd_flow::review::parse`, FORMAT.md): `gate open review` is refused with `doc_schema` when one has no valid severity, and the gate is held for a major or blocker finding that is not `resolved` (it names tasks and all are done). `GET /agents/{id}/findings` serves them with `resolved` to the UI (`components/Findings.svelte`, shown above `review.md` in the Documents panel). Severity colours are `--sev-blocker`, `--sev-major`, `--sev-minor` (+ `-wash`) in `app.css`, never `--gate`; each also has a glyph and its name.

PR polling (R-303, R-305, R-307): the scheduler's 30 s `PrPoll` tick makes `Actor::poll_pr` ask the host for a `pr::Snapshot` of a **watching** agent's PR when `pr_poll` (`prPollMinutes`, default 5, 0 = off; `Options::pr_poll` overrides it for tests) has passed since `Agent.pr_polled_at`; the answer returns as `WorkResult::PrPoll`. `Agent::apply_pr` (pure, `xherd_core::pr`) keeps `pr_state`, `pr_ci`, `pr_ci_failed`, `pr_conflict`, and for the PR panel (#75) `pr_checks` (`CheckRun` with `workflow`/`link`; the UI links only https), `pr_reviewers` (`Reviewer {name, state}`; built-in `github` merges `reviewRequests` (= `pending`, also when asked again) and `latestReviews` in `github_status`) and `pr_mergeable`, and returns the news. When the host says nothing about mergeability (`Unknown`; GitHub computes it lazily, `mergeStateStatus: DIRTY` counts as a conflict), the poll task runs `local_mergeable`: `git fetch origin`, then `Git::merges_cleanly` (`git merge-tree --write-tree`, git ≥ 2.38, exit 1 with a tree on stdout = conflict) of `HEAD` into `origin/<base>` (the host's `base`, else `Agent.base`); a failed fetch leaves it unknown. The news: checks start failing, all pass again after failing, a merge conflict (each said once), merged/closed (`Trigger::PrFinished` → `done`). A failed poll is logged (`pr-poll-failed`), never fatal. PR comments (R-304): the same poll also reads `Host::pr_comments` (built-in `github`: `gh api --paginate` on `pulls/N/comments`, `issues/N/comments`, `pulls/N/reviews`; ids are `<kind>:<id>`, `parse_stream` handles one JSON array per page; an external plugin answers `pr-comments`). `Agent::new_comments` (pure) returns the ids not in `pr_comments_seen` and not carrying `pr::MARKER` (`<!-- xherd -->`, what xherd's own replies will have). `Actor::on_new_comments` writes `.xherd/spec/pr-comments.json` (`{"comments": [...]}`, **every body wrapped with `untrusted::wrap`**; a failed write un-marks them), sets `next_prompt` to the pack command `prReview` and fires `Trigger::PrComments` (watching → queued, fresh session); flow `none` is only notified. Notifications never carry comment text. The pack has the stage `pr-review` (docs gate `pr-review.md`, next `/xherd:pr-apply`) between `ship` and `pr`; `pr-apply` turns `fix` decisions into tasks with `source: pr`, implements them, pushes the branch and leaves reply drafts for the user to post. Decisions (R-306, `pr_round.rs`): `xherd_flow::pr_review::parse` reads `pr-review.md` (`### <comment id>` + `- decision: fix|reply|skip`, `- reason:`, `- reply:`); `gate open pr-review` is refused (`doc_schema`) unless `pr::decide` finds one decision per comment of the round and a text for each `reply`. The round's files: `.xherd/pr-comments-raw.json` (raw comments for the UI), `.xherd/pr-overrides.json` (the user's decisions from `PUT /agents/{id}/pr-decisions` and the ids of posted replies; replaced when a new round starts), `.xherd/spec/pr-decisions.json` (final, for `pr-apply`). Board (`#/board`, `pages/Board.svelte`, read-only): units of work in Pending / In progress / Done. TODOs (`#/todos`, `pages/Todos.svelte`, `xherd_core::todo` pure lifecycle `open → checking → due → done | error`, `xherd_daemon::todos`, table `todos` as JSON): reminders due at a time, once or repeating (`repeatMinutes` ≥ 5; completing a repeating one jumps to the next time after now), and **condition checks** (spec §16.2): a TODO with a `condition` (words) and `repeatMinutes` = the check interval is checked at each due time. `Daemon::todo_tick` runs on the 30 s poll tick: a TODO whose time has come becomes `due` and publishes `Change::Notify {agent_id: "todo:<id>", kind: "todo"}` once (skipped when `todo` is in `mutedNotifications`; the UI opens `/todos` for such notices). API: `GET/POST /todos`, `PUT/DELETE /todos/{id}`, `POST /todos/{id}/complete`, `POST /todos/{id}/reschedule {due}`. They are not agents and never count against the cap (R-006). A check (`Daemon::spawn_check` / `run_check`, `POST /todos/{id}/check` = "check now") is one headless run of the default runtime as the agents' user (`Cmd::as_agent`, cwd = the workspace, `CHECK_TIMEOUT` 2 min): the runtime plugin's `data.terminal.check` (`xherd_plugin::runtime::Check`: `argv` with `{prompt}` and `{system}` once each, optional `modelArgs` with `{model}`; Claude Code: `claude -p … --allowedTools` read-only tools and `gh`/`git` read commands, `--disallowedTools Edit Write NotebookEdit`, `--no-session-persistence`; a runtime without `check` cannot check, the TODO goes to `error`). The run must end with `XHERD_RESULT {"met": bool, "summary": "…"}` (`todo::parse_result`, last such line wins): met or no/unclear answer or timeout → `due` (notified, you look), not met → `open` at the next interval, run failed → `error`; a check lost to a restart (`CHECK_STALE_MS`) becomes `error`. The summary is model output: shown on the page, never in notifications. `model` is validated to plain characters (it goes on a command line). Keep any new `check` argv read-only: that is the only thing that makes a check safe.

## Running it

```sh
XHERD_HOME=/tmp/xh cargo run -p xherd-cli -- daemon     # JSON logs on stderr; XHERD_LOG=debug for more
XHERD_HOME=/tmp/xh cargo run -p xherd-cli -- status
XHERD_HOME=/tmp/xh cargo run -p xherd-cli -- install  # /xherd:* commands into ${CLAUDE_CONFIG_DIR:-~/.claude}/commands/xherd/
```

No trust step is needed: xherd marks each new worktree trusted in Claude Code's config. Claude Code must be logged in (`claude`, then `/login`, once).

In Docker, everything inside the container (daemon, UI, tmux, Claude Code, toolchains), only the workspace shared:

```sh
cd deploy/compose
printf 'XHERD_WORKSPACE=%s/xherd\nXHERD_UID=%s\nXHERD_GID=%s\n' "$HOME" "$(id -u)" "$(id -g)" > .env
mkdir -p ~/xherd && docker compose up -d --build     # http://127.0.0.1:4740/
```

The UI (needs Node and pnpm; cargo does not run it):

```sh
cd ui && pnpm install && pnpm build     # ui/dist, served by the daemon at http://127.0.0.1:4740/
cd ui && pnpm dev                        # Vite dev server, proxies /api to XHERD_URL (default 127.0.0.1:4740)
cd ui && pnpm check                      # svelte-check (types)
```

Data root: `XHERD_HOME`, else `$XDG_DATA_HOME/xherd`, else `~/.local/share/xherd`. `config.json` there holds the port (4740), `tmuxSocket` and the generated user token used by the CLI.

## Conventions

- Edition 2024, workspace lints: `unsafe_code = "forbid"`, clippy `all` = warn (CI denies warnings).
- External commands only through `xherd_core::exec::run` (argv, no shell, timeout + process-group kill, env allowlist, redaction). Exceptions: the interactive tmux client of a browser terminal (`xherd_term::pty`), still with an env allowlist; processes that replace the CLI (`toolchain exec`, `attach`, `shell`, `init` → daemon); long-lived helpers (`socat` in `init`, apps launched by `open`/`companion`).
- State changes to an agent only inside its actor, through pure functions in `xherd-core`; slow work returns as `WorkDone` tagged with the agent's `generation`.
- `xherd hook` / `xherd report` must never print to stdout or exit non-zero, and must not start tokio (fast path, R-012, R-901).
- JSON on the wire and in files is camelCase; enum values are kebab-case.
- Files the daemon writes go through `paths::write_atomic`; secrets are mode 0600.
- Minimal code: no abstraction for a single use; flag unrelated problems instead of fixing them silently.
- Clean room: never copy or name proprietary tools, prompts, texts or design tokens from other products.

## Gotchas

- `target/` size: `[profile.dev] debug = "line-tables-only"` in `Cargo.toml` and `incremental = false` in `.cargo/config.toml` keep it small (about 30 test binaries each link the whole tree). Remove the second if rebuild speed matters more than disk; `cargo clean` is always safe.

- Version (issue #53): `xherd_core::VERSION` is the Cargo version (compatibility checks, store, backups compare it; do not display-format it). `xherd_core::BUILD_VERSION` (`crates/xherd-core/build.rs`) is what people see (`xherd --version`, `/state` `buildVersion`, the bar next to the logo, Settings → About): the git tag of a release (`0.2.0`), `<tag>+<commits>.<hash>` after it, `<cargo version>+<hash>` before the first tag, `.dirty` for uncommitted changes. `XHERD_VERSION` in the environment overrides it; the Docker image has no `.git`, so pass `--build-arg XHERD_VERSION=$(git describe --tags --always)` (compose does not yet).
- Toolchain installs (issue #48): the install command is wrapped in `sh -c` that waits for Enter when it fails, so the terminal stays and shows the error; the version list is sorted newest first by `natural_cmp`.

- opencode (checked with 1.19): the TUI's input is not ready when plugins load (about 1 s later), so typed text is lost: deliver a session's first prompt with `promptArgs`, never by typing at `session-start`. `--prompt` is ignored with `--session` (use `resume.promptEnv`). `opencode export` through a pipe is cut at 64 KiB most of the time: export to `{file}`. The plugin runs in a worker (`process.argv` is not opencode's) and sees no TUI readiness event. Subagent sessions (`session.created` with `parentID`) must not report stops. The `permission.ask` plugin hook is never called; the `permission.asked` bus event is. The TUI remembers the last model used and prefers it to `model` in the config.
- tmux takes a new session's `PATH` from the client that creates it, not from `new-session -e PATH=…` (checked with tmux 3.6b): the agents' `PATH` is the daemon's. Installed builds are fine (`/usr/bin/xherd` from the packages, `/usr/local/bin` in the image); a daemon run from source must have `target/debug` on its own `PATH`, or the prompts' plain `xherd …` calls fail with "command not found".
- `xherd hook` is handled in `main` **before** clap, inside `catch_unwind` with a silent panic hook, so bad arguments or panics still exit 0 with no output. Keep it that way.
- Sequence numbers from the CLI are `max(last + 1, now in µs)` (`.xherd/seq`), so counter-based and time-based reports from the same agent stay ordered.
- Hooks without a token, or with the daemon unreachable / 5xx, are appended to `hook-queue.jsonl`; 4xx answers are not queued (a retry would not help). The daemon replays the queue at start and every minute.
- `rusqlite` is pinned to the version `rusqlite_migration` uses (both link `sqlite3`); bump them together.
- `ureq` 3 treats HTTP errors as `Err` unless `http_status_as_error(false)`; the CLI sets it.
- In axum handlers, read the peer address through the `ConnectInfo` extractor (not `extensions.get`) so `MockConnectInfo` works in tests.
- YAML is parsed with `yaml_serde` (the maintained serde_yaml). It expects `!Tag` syntax for enums; pack enums written as one-key maps (`Condition`) go through a raw struct with `try_from`.
- Pack manifests use `deny_unknown_fields`: fields not implemented yet (`views`, `extends`, `parse`…) are rejected, not ignored.
- XAP calls are de-duplicated by call id through the events table (`xap.<cmd>` events use the call id). A replayed call answers `{"changed": false, "duplicate": true}`.
- XAP observation (file reads, git) runs inline in the actor; keep it to small local reads.
- Gate documents are hashed with `xherd_flow::approve::doc_sha256`, never `content_sha256` directly: in the tasks-stage document the `- status:` / `- evidence:` lines of task sections, and whole task sections with `source: review` or `source: pr`, are dropped first (`tasks::without_progress`), so progress and the fix tasks a review or PR round adds do not re-open the tasks gate (R-107; otherwise `infer_gate` reopens Tasks at the first gate-less stop after the review). Use it at every place that records or compares a gate-document hash.
- Approval hashes what is on disk at approval time (the user approves what they read), not the hash recorded at `gate open`. Commit-gate files are recorded as `./<path>`; deleted files as `deleted`.
- On start the daemon re-imports every agent's `approvals.jsonl` into the table (`INSERT OR IGNORE`): the file wins.
- A fresh session respawns only the `agent` window (`respawn-window -k`); the tmux session, its environment (`XHERD_*`, the agent token) and other windows stay. The new process gets the variables because `new-session -e` puts them in the session environment.
- The daemon writes only the progress lines of agent documents (D11, relaxed): after a successful `task start|done|block` the task's `- status:` (and `- evidence:`, one line, newlines joined with ` | `) in `.xherd/spec/tasks.md`; after `commit propose|done|drop` and the commit made on approval the entry's `- status:` / `- sha:` in `commits.md` (`xherd_flow::progress`, called from `Actor::write_progress`). Nothing else is touched, no entries are created; a missing file or entry is skipped (debug log), never an error. Task blocked reasons have no line in the format and are not written.
- `task done` runs the task's `verify:` in the daemon (R-118, `Actor::run_verify`): `sh -c <verify>` in the worktree through `exec::run` (the daemon's allowlisted env; the agent could run the same command anyway), limit `ActorSettings::verify_timeout` (10 min; `Options::verify_timeout` for tests). It is a deliberate inline exception to "slow work returns as `WorkDone`", like `commit_for_user`: the agent waits for the answer anyway. The result reaches the pure `xap::apply` as `Observed::Verify`; replayed call ids never rerun it (`on_xap` checks the id first), and a task already done is not re-verified.
- `gate open` and `commit propose` of an xherd flow need a valid `.xherd/spec/memory.md` (`xherd_flow::memory::check`, called from `Actor::observe`, refusal `memory_invalid`): the four `##` sections and at most 80 lines, nothing else. Tests that open gates get a valid one from `setup` in `tests/xap.rs`.
- Approving a parked agent stores the next command in `agent.next_prompt` and queues it; it is typed at the next `session-start` hook, like a new agent's first command. Every other action on a parked agent must also work, since it has no session to type into: Resume queues it with the pack's `resume` command (the gate stays open), and Send / Request changes store their text in `next_prompt`, unpark it and continue the last conversation when the transcript is found (`Actor::unpark_with`); a Send while a question is open still answers it. Pause and Cancel work as usual.
- Worktrees live at `<workspace>/worktrees/<repo dir name>/<agent>`; workspace = `config.workspace`, else `$XHERD_WORKSPACE`, else `~/xherd` (design §8.1). Tests must set `workspace` in `config.json` or they write to the real `~/xherd`.
- Runtime trust (design §4.1): `TrustWriter` (`create.rs`) sets the runtime plugin's `data.terminal.trust` key for the agent's worktree only (paths under `<workspace>/worktrees`, as stored and canonicalised), at creation and in `Actor::session_argv` before every start; other keys are kept and a non-JSON file is never overwritten (`runtime_trust`). Tests that create agents must point `trust.file` of the built-in `claude-code` manifest at a fixture (see `tests/create.rs` setup), never the real `~/.claude.json`.
- A repository URL becomes `<workspace>/repos/<host>/<owner…>/<repo>`; https and ssh forms of the same repo share one clone. Clones and fetches run with `GIT_SSH_COMMAND` in batch mode (`xherd_git::NO_PROMPT`), so a missing key or host key fails instead of hanging. `new_agent` clones before its other checks, so a refused agent still leaves the clone (reused next time).
- Pre-push guard (R-1204): each worktree gets `.xherd/hooks/` as its own `core.hooksPath` (`extensions.worktreeConfig` + `git config --worktree`), holding symlinks to the repo's other hooks (so they still run) and a `pre-push` that pipes git's stdin to `xherd guard pre-push` and then to the original `pre-push`. `git push --no-verify` skips it: it stops mistakes, branch protection on the host is the real boundary. Test: `crates/xherd-cli/tests/push_guard.rs` (real git, bare remote).
- Secret tripwire patterns live in `xherd_core::tripwire` (prefix + character class + minimum length, at a word boundary; `.env`-like files flag any non-empty, non-placeholder value). Findings are masked to four characters; never put the matched text in a message.
- `.xherd/` is excluded through the repo's shared `.git/info/exclude` (one line covers every worktree).
- A new agent's first command (the flow's `start`, or the prompt for flow `none`) is stored in `agent.next_prompt` and typed when the runtime's `session-start` hook reports, with the pack's `slashEnters` when it starts with the pack prefix. No hook (e.g. the runtime shows a dialog: `xherd attach NAME` and answer it) = nothing typed yet. The command stays in `next_prompt` until the runtime accepts a prompt (`user-prompt-submit`, `Actor::first_unacked`): Claude Code 2.1.319 fires `SessionStart` twice about a second apart and drops text typed after the first, so every `session-start` before the ack types it again.
- The runtime's hook file (`.claude/settings.local.json`) is written at creation, not at each launch: xherd's entries (command ends with `# xherd`) are replaced, the user's kept; invalid JSON refuses creation. Hook commands use the daemon's absolute `xherd` path; the token and agent id come from the session environment.
- `Options::new` loads the built-in plugins (`xherd_plugin::builtins()`); clear `builtin_plugins` to test a missing runtime.
- A new file in `packs/xherd/` must be added to `xherd_flow::install::BUILTIN_FILES` (a test compares the folder with the list).
- Prompts teach XAP as plain `xherd <call>` inside backticks on one line, with concrete example values (never `"$XHERD_BIN"`: Claude Code cannot check a command with a variable and asks every time; the session `PATH` starts with xherd's folder and the worktree's `permissions.allow` lists the XAP subcommands, `XAP_ALLOW` in `create.rs`): the CLI test `prompt_calls_parse` parses every such call with clap, and `every_template_has_a_prompt` checks each manifest command has a `commands/<name>.md`.

In the container (`sandbox`) loopback does **not** count, because that is where the agents are (R-1203, T2): only `local_peers` (the gateway the published port arrives from) has address rights, and the CLI there needs its user token (an unissued token is no longer ignored on loopback). - Two users in the container (R-1203, branch `m4-user-split`; design §8.4): `xherd init` creates `xherd-daemon` (ids from 10001, own volume `xherd-data` at `/var/lib/xherd-daemon`, `data/` 0700, `shared/` readable), starts `xherd runner` as the agents' user, then drops to the daemon's user (PATH = system dirs only, umask 002, in the host's group). `XHERD_RUNNER` makes the daemon send `Cmd::as_agent()` commands and `runner::{read_file, write_file, mkdir, find_in_subdirs_as_agent}` there (git, `verify:`, host/plugin commands and checks, the git-access doctor's ssh/git calls, the runtime's trust and hook files, pack commands, transcripts, `info/exclude`, clone cleanup); all of them act in place without a runner (native, tests). `XHERD_AGENT_<NAME>` (`XHERD_AGENT_HOME`, `XHERD_AGENT_PATH`) is what `runner::agent_env` returns instead of the daemon's own `HOME`/`PATH`: use it wherever the value is the agents' (pack destinations, session PATH). The runner also supervises the tmux server (`--tmux`, socket `/run/xherd/tmux.sock`, `Tmux` uses `-S` for a path; the daemon's user gets in through `server-access` set by the runner, not by the config file, which tmux reads only when the first client connects); the runner opens its own socket only after that access is set (or 20 s), since the daemon starts sessions as soon as the runner answers: a resume at start once failed with `Permission denied` on the tmux socket and left the agent in `error`). Shared, not through the runner: each worktree's `.xherd/` (`runner::mkdir`, mode 2775), `<workspace>/{worktrees,repos}`, `/run/xherd` (sockets and the hook queue, `XHERD_QUEUE`, mode 0660 when set). The daemon reads worktree files as itself: they must be group/world-readable. The managed gitconfig is `$XHERD_SHARED/gitconfig`. A CLI run as `xherd-daemon` finds `/var/lib/xherd-daemon/data` by itself (`Paths::from_env`); run as the agents' user it has no token (that is the point). Checked on Colima (processes, 401 on loopback, isolation, shared tmux, queue, agent creation and diff); Colima's mounts do not enforce ownership, so **file permissions need a Linux host**. Not done: a Setup check for a runner that dies after start, `access: device` pairing (server milestone), per-user `docker exec` hints in `xherd docker doctor`.
