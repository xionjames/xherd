# AGENTS.md

Guidance for coding agents (Claude Code, Codex, opencode…) working in this repository. **Keep this file current**: when you add a crate, a command, a convention or a gotcha, update it in the same change.

## What this is

xherd: a daemon (Rust) that runs, watches and steers many coding agents, each in its own git worktree and tmux session, with approval gates. Read before changing behaviour:

- `doc/spec.md` — what (requirements `R-xxx`)
- `doc/design.md` — how (crates, architecture, milestones §18, decisions §19)
- `doc/xap.md` — agent protocol (`xherd hook|report|gate|task|commit …`)
- `ROADMAP.md` — what is left, by theme (the milestone checklist in `doc/design.md` §18 stays the source of truth; update both)

Decisions in `doc/design.md` §19 are settled; do not re-open them in code. Cite requirement ids (`R-009`) in doc comments where code implements one.

M1 scope decisions: approvals from the CLI only (the UI comes in M2); xherd v0 ships the `feature` flow only. `xherd new` / `POST /api/v1/agents` create agents (worktree + `.xherd/` + Claude Code hooks) that start: the built-in `claude-code` runtime plugin gives the launch argv (`claude`, permission mode `edits`, the default; `ask` is the strict one), the daemon starts it in a tmux session named after the agent, and types the flow's start command once the runtime's `session-start` hook arrives. Approving a gate starts a **fresh session** (`freshSessions`, default on; R-023): the agent window's process is respawned with `agent.launch` and the next command is typed on the new `session-start`; with it off, the command is typed into the current session. Resume starts with the pack's `resume` command unless a next prompt is pending (R-027). Commit gates are reviewed with `xherd diff <agent>` / `GET /agents/:id/diff` before `xherd approve`; at the ship gate (`pr.md`) the same diff shows the branch as it will be pushed (`<agent.base>...HEAD`). Approving the ship gate hands on `/xherd:ship`, and the **agent** pushes and opens the draft PR (the daemon never pushes), then reports `xherd pr opened`; a flow agent that stops idle with `pr_url` set and no gate ends its session and goes to `watching` (R-301). If it stops in the ship stage without reporting one, the daemon asks the host plugin (`pr-for-branch`, built-in `github` through `gh`; R-302). `xherd ls` shows the PR once no gate is open. There is no autonomy in M1, so the ship stage's `autoApproved` variant (`--no-ticket-update`) is never used; the pre-push guard (R-1204) is a guardrail (M4) and PR polling is PR follow-up (M4); code tripwires on commits (R-115…R-117, incl. the secret tripwire) and `diff_viewed` marks are M4/M2. Not done yet: pause with a handoff (R-026, pause just ends the session), the background-task guard of R-024 (no data source), runtime change between steps (R-025, one runtime), resuming the runtime's own session.

## Running it

```sh
XHERD_HOME=/tmp/xh cargo run -p xherd-cli -- daemon     # JSON logs on stderr; XHERD_LOG=debug for more
XHERD_HOME=/tmp/xh cargo run -p xherd-cli -- status
XHERD_HOME=/tmp/xh cargo run -p xherd-cli -- install  # /xherd:* commands into ${CLAUDE_CONFIG_DIR:-~/.claude}/commands/xherd/
```

No trust step is needed: xherd marks each new worktree trusted in Claude Code's config. Claude Code must be logged in (`claude`, then `/login`, once).

In Docker, everything inside the container (daemon, UI, tmux, Claude Code, toolchains), only the workspace shared:

```sh
cd deploy/compose
printf 'XHERD_WORKSPACE=%s/xherd\nXHERD_UID=%s\nXHERD_GID=%s\n' "$HOME" "$(id -u)" "$(id -g)" > .env
mkdir -p ~/xherd && docker compose up -d --build     # http://127.0.0.1:4740/
```

The UI (needs Node and pnpm; cargo does not run it):

```sh
cd ui && pnpm install && pnpm build     # ui/dist, served by the daemon at http://127.0.0.1:4740/
cd ui && pnpm dev                        # Vite dev server, proxies /api to XHERD_URL (default 127.0.0.1:4740)
cd ui && pnpm check                      # svelte-check (types)
```

Data root: `XHERD_HOME`, else `$XDG_DATA_HOME/xherd`, else `~/.local/share/xherd`. `config.json` there holds the port (4740), `tmuxSocket` and the generated user token used by the CLI.

## Build and test

Rust is installed through Homebrew's keg-only `rustup`; add it to `PATH` if `cargo` is missing:

```sh
export PATH=/opt/homebrew/opt/rustup/bin:$PATH
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
cargo fmt --all --check
```

Integration tests need `git` and `tmux` (≥ 3.3) on `PATH`; tmux tests use a private socket (`-L xherd-test-…`) and never touch your sessions.

## Conventions

- Edition 2024, workspace lints: `unsafe_code = "forbid"`, clippy `all` = warn (CI denies warnings).
- External commands only through `xherd_core::exec::run` (argv, no shell, timeout + process-group kill, env allowlist, redaction). Exceptions: the interactive tmux client of a browser terminal (`xherd_term::pty`), still with an env allowlist; processes that replace the CLI (`toolchain exec`, `attach`, `shell`, `init` → daemon); long-lived helpers (`socat` in `init`, apps launched by `open`/`companion`).
- State changes to an agent only inside its actor, through pure functions in `xherd-core`; slow work returns as `WorkDone` tagged with the agent's `generation`.
- `xherd hook` / `xherd report` must never print to stdout or exit non-zero, and must not start tokio (fast path, R-012, R-901).
- JSON on the wire and in files is camelCase; enum values are kebab-case.
- Files the daemon writes go through `paths::write_atomic`; secrets are mode 0600.
- Minimal code: no abstraction for a single use; flag unrelated problems instead of fixing them silently.
- Clean room: never copy or name proprietary tools, prompts, texts or design tokens from other products.

## Gotchas

- `xherd hook` is handled in `main` **before** clap, inside `catch_unwind` with a silent panic hook, so bad arguments or panics still exit 0 with no output. Keep it that way.
- Sequence numbers from the CLI are `max(last + 1, now in µs)` (`.xherd/seq`), so counter-based and time-based reports from the same agent stay ordered.
- Hooks without a token, or with the daemon unreachable / 5xx, are appended to `hook-queue.jsonl`; 4xx answers are not queued (a retry would not help). The daemon replays the queue at start and every minute.
- `rusqlite` is pinned to the version `rusqlite_migration` uses (both link `sqlite3`); bump them together.
- `ureq` 3 treats HTTP errors as `Err` unless `http_status_as_error(false)`; the CLI sets it.
- In axum handlers, read the peer address through the `ConnectInfo` extractor (not `extensions.get`) so `MockConnectInfo` works in tests.
- YAML is parsed with `yaml_serde` (the maintained serde_yaml). It expects `!Tag` syntax for enums; pack enums written as one-key maps (`Condition`) go through a raw struct with `try_from`.
- Pack manifests use `deny_unknown_fields`: fields not implemented yet (`views`, `extends`, `parse`…) are rejected, not ignored.
- XAP calls are de-duplicated by call id through the events table (`xap.<cmd>` events use the call id). A replayed call answers `{"changed": false, "duplicate": true}`.
- XAP observation (file reads, git) runs inline in the actor; keep it to small local reads.
- Gate documents are hashed with `xherd_flow::approve::doc_sha256`, never `content_sha256` directly: in the tasks-stage document the `- status:` / `- evidence:` lines of task sections are dropped first (`tasks::without_progress`), so progress does not re-open the tasks gate (R-107). Use it at every place that records or compares a gate-document hash.
- Approval hashes what is on disk at approval time (the user approves what they read), not the hash recorded at `gate open`. Commit-gate files are recorded as `./<path>`; deleted files as `deleted`.
- On start the daemon re-imports every agent's `approvals.jsonl` into the table (`INSERT OR IGNORE`): the file wins.
- A fresh session respawns only the `agent` window (`respawn-window -k`); the tmux session, its environment (`XHERD_*`, the agent token) and other windows stay. The new process gets the variables because `new-session -e` puts them in the session environment.
- The daemon writes only the progress lines of agent documents (D11, relaxed): after a successful `task start|done|block` the task's `- status:` (and `- evidence:`, one line, newlines joined with ` | `) in `.xherd/spec/tasks.md`; after `commit propose|done|drop` and the commit made on approval the entry's `- status:` / `- sha:` in `commits.md` (`xherd_flow::progress`, called from `Actor::write_progress`). Nothing else is touched, no entries are created; a missing file or entry is skipped (debug log), never an error. Task blocked reasons have no line in the format and are not written.
- `task done` runs the task's `verify:` in the daemon (R-118, `Actor::run_verify`): `sh -c <verify>` in the worktree through `exec::run` (the daemon's allowlisted env; the agent could run the same command anyway), limit `ActorSettings::verify_timeout` (10 min; `Options::verify_timeout` for tests). It is a deliberate inline exception to "slow work returns as `WorkDone`", like `commit_for_user`: the agent waits for the answer anyway. The result reaches the pure `xap::apply` as `Observed::Verify`; replayed call ids never rerun it (`on_xap` checks the id first), and a task already done is not re-verified.
- `gate open` and `commit propose` of an xherd flow need a valid `.xherd/spec/memory.md` (`xherd_flow::memory::check`, called from `Actor::observe`, refusal `memory_invalid`): the four `##` sections and at most 80 lines, nothing else. Tests that open gates get a valid one from `setup` in `tests/xap.rs`.
- Approving a parked agent stores the next command in `agent.next_prompt` and queues it; it is typed at the next `session-start` hook, like a new agent's first command.
- Worktrees live at `<workspace>/worktrees/<repo dir name>/<agent>`; workspace = `config.workspace`, else `$XHERD_WORKSPACE`, else `~/xherd` (design §8.1). Tests must set `workspace` in `config.json` or they write to the real `~/xherd`.
- Runtime trust (design §4.1): `TrustWriter` (`create.rs`) sets the runtime plugin's `data.terminal.trust` key for the agent's worktree only (paths under `<workspace>/worktrees`, as stored and canonicalised), at creation and in `Actor::session_argv` before every start; other keys are kept and a non-JSON file is never overwritten (`runtime_trust`). Tests that create agents must point `trust.file` of the built-in `claude-code` manifest at a fixture (see `tests/create.rs` setup), never the real `~/.claude.json`.
- A repository URL becomes `<workspace>/repos/<host>/<owner…>/<repo>`; https and ssh forms of the same repo share one clone. Clones and fetches run with `GIT_SSH_COMMAND` in batch mode (`xherd_git::NO_PROMPT`), so a missing key or host key fails instead of hanging. `new_agent` clones before its other checks, so a refused agent still leaves the clone (reused next time).
- Pre-push guard (R-1204): each worktree gets `.xherd/hooks/` as its own `core.hooksPath` (`extensions.worktreeConfig` + `git config --worktree`), holding symlinks to the repo's other hooks (so they still run) and a `pre-push` that pipes git's stdin to `xherd guard pre-push` and then to the original `pre-push`. `git push --no-verify` skips it: it stops mistakes, branch protection on the host is the real boundary. Test: `crates/xherd-cli/tests/push_guard.rs` (real git, bare remote).
- Secret tripwire patterns live in `xherd_core::tripwire` (prefix + character class + minimum length, at a word boundary; `.env`-like files flag any non-empty, non-placeholder value). Findings are masked to four characters; never put the matched text in a message.
- `.xherd/` is excluded through the repo's shared `.git/info/exclude` (one line covers every worktree).
- A new agent's first command (the flow's `start`, or the prompt for flow `none`) is stored in `agent.next_prompt` and typed when the runtime's `session-start` hook reports, with the pack's `slashEnters` when it starts with the pack prefix. No hook (e.g. the runtime shows a dialog: `xherd attach NAME` and answer it) = nothing typed yet. The command stays in `next_prompt` until the runtime accepts a prompt (`user-prompt-submit`, `Actor::first_unacked`): Claude Code 2.1.319 fires `SessionStart` twice about a second apart and drops text typed after the first, so every `session-start` before the ack types it again.
- The runtime's hook file (`.claude/settings.local.json`) is written at creation, not at each launch: xherd's entries (command ends with `# xherd`) are replaced, the user's kept; invalid JSON refuses creation. Hook commands use the daemon's absolute `xherd` path; the token and agent id come from the session environment.
- `Options::new` loads the built-in plugins (`xherd_plugin::builtins()`); clear `builtin_plugins` to test a missing runtime.
- A new file in `packs/xherd/` must be added to `xherd_flow::install::BUILTIN_FILES` (a test compares the folder with the list).
- Prompts teach XAP as plain `xherd <call>` inside backticks on one line, with concrete example values (never `"$XHERD_BIN"`: Claude Code cannot check a command with a variable and asks every time; the session `PATH` starts with xherd's folder and the worktree's `permissions.allow` lists the XAP subcommands, `XAP_ALLOW` in `create.rs`): the CLI test `prompt_calls_parse` parses every such call with clap, and `every_template_has_a_prompt` checks each manifest command has a `commands/<name>.md`.
- `xherd install` runs in the daemon (`POST /api/v1/install`), so commands land where the agents run (user level, per the pack's `install.<runtime>.commands.to`). Run it once before the first agent; nothing installs automatically yet. Tests call `Daemon::install` with their own `env` closure: never let a test resolve the real `HOME`.
- `Git::diff_proposed` stages the proposed files into a temporary `GIT_INDEX_FILE` (with `--force`, so proposed ignored files show) and never touches the worktree's index; paths are literal (`--literal-pathspecs`). Output is capped at 4 MiB by `exec::run` (silently truncated).
- `approve` takes an optional `expect` (document → hash the UI read, from `GET /file`); a mismatch refuses with `changed_since_read`, so a UI approval covers exactly what was shown. The CLI sends none (hashes what is on disk).
- A runtime `Notification` while the agent is stopped (`waiting-input`, `idle`) is an idle reminder (Claude Code: `notification_type: idle_prompt`, about a minute after a stop) and changes nothing; only mid-turn notifications (permission prompts) or `report --state blocked` set `blocked`. A blocked agent cannot be approved.
- `Agent.visited_stages` records every stage the agent entered (added in `Actor::commit`, so every stage change counts); the UI shows earlier stages missing from it as skipped. Agents saved before the field existed get it rebuilt once from their `xap.stage.enter` / `xap.gate.open` events when their actor starts.
- A question gate (`xherd ask`) is not approved: `xherd send` while it is open is the answer, clears the gate and logs `user.answer`.
- Toolchains (R-652): at every session start (`Actor::session_argv`, also for fresh sessions) the daemon writes `.xherd/toolchain.json` from the worktree's version files and starts `xherd toolchain exec -- <launch>`; no version files = the runtime starts directly and the plan file is removed. Installing happens only with `XHERD_SANDBOX=1` in the daemon's environment (`Options::sandbox`). `exec::Cmd::inherit_output` shows install logs live in the window. The final `exec` of the runtime is the second exception to `exec::run`.
- Container mode (`XHERD_SANDBOX=1`, set by the image): toolchains install, the xherd commands are installed at every daemon start, `XHERD_BIND` overrides `config.bind` (`0.0.0.0`), and `XHERD_LOCAL_PEERS` (the gateway, from `xherd init`) counts as loopback for local rights (`Daemon::local_peers`). Safe only because compose publishes the port on the host's `127.0.0.1`. Single user: the daemon and the agents share one user (Setup check `single-user` says so).
- Never write into the real `$HOME` from code that tests start: the managed gitconfig goes to the data root unless `sandbox`; `Daemon::start` with `sandbox` installs commands with the process env, so tests never set `Options::sandbox`.
- Agent tokens carry `hooks`, `xap` and `credential` scopes; `POST /git/credential` takes the local user or such a token.
- `Tmux::send_text` pauses 300 ms before each Enter: typed text and Enter sent back to back are taken as one paste by Claude Code and the Enter is dropped (the delivery retry then rescues it 10 s later).
- Supervisor messages carry `oneshot` replies straight to the caller; the supervisor never awaits an actor.
- A bearer token this daemon never issued, on an otherwise local request, is ignored (the host CLI of a native install sends its own token to the container); agent and revoked tokens are still refused.
- Local browsers get full rights by address (loopback peer, local Host, no proxy headers) **and** a local or absent `Origin`: a request carrying another site's `Origin` is refused (no cross-site requests or websockets).
- Debug builds serve `ui/dist` from disk (rebuild the UI, reload the page); release builds embed it at compile time, so build the UI before `cargo build --release`.
- UI panels key effects on `const id = $derived(agent.id)`, never `agent.id` directly: the agent object is replaced on every websocket update, and reading it in an effect would reconnect terminals and refetch on each change.
- `Change` (hub messages, `/ws`) is tagged `type` (kebab-case) with camelCase fields.
- UI theme: no saved choice follows the OS (`prefers-color-scheme`); the bar button flips what is visible (light ⇄ dark, never a click that changes nothing), Shift+click goes back to following the system (`lib/theme.svelte.ts`). The choice is `data-theme` on `<html>` and `localStorage` `xherd.theme`; an inline script in `index.html` sets it before the first paint, and `app.css` sets `color-scheme` to match, so native controls follow it. The terminal stays dark in both.
- UI: `--gate` (coral) means "needs a human" and nothing else; agent hues avoid it. Status is never colour alone (pair with a label or glyph).
- The UI blocks every screen but Setup checks and Settings while a required check fails, and sends a first-run user (`config.welcomed` false in the saved config) to `#/welcome`.
- Built-in plugin checks run their argv as written (`gh --version`), ignoring settings such as `pluginSettings.github.gh`; tests that run `Daemon::checks` keep only a runtime plugin with a harmless check (see `tests/checks.rs`) and pass their own `env` (HOME) so the pack check never reads or writes the real `~/.claude`.
- Plugins can be switched off (`config.json` `disabledPlugins`, Welcome step 3): read live from the saved config by `Daemon::plugin_enabled`, no restart. Live today: Setup checks skip them, `new_agent` refuses a disabled runtime, `/state` reports `enabled`. **Not live yet:** the host (`Env.host`), trust writer and toolchain list are built once at daemon start. `save_config` refuses unknown names and switching off the last plugin of a kind. A plugin with a manifest `login` argv gets `POST /plugins/{name}/login` (tmux session `xherd-setup-plugin-login`, shown at `/ws/setup/plugin-login`); whether it is logged in is its check named `login` (`claude auth status` for `claude-code`; required for the default runtime, so a logged-out Claude holds Welcome step 3 and Setup).
- Container/terminal-server restart: `Daemon::start` reconciles with `recover` (`TickKind::SessionCheck { recover: true }`). A live agent whose tmux session is gone is **parked** when it waits at a docs/commit gate (approving works, the fresh session starts with the next command), else it gets `session-lost` and is resumed like `Resume` (pack `resume` command). The periodic (60 s) reconcile still fails a vanished session (`error`), since then the agent really died.
- xherd steps are new sessions with no history: `memory.md` (State / Decisions / Code map / Watch out, `FORMAT.md`) is what carries over, so each command reads it first and rewrites it before its gate. Keep that wording when editing the commands (D23).
- Resume (`Actor::prepare_resume`, used by the Resume action, restart recovery and auto-resume): the pack `resume` command is typed, and when the runtime plugin's `data.terminal.resume` (`--resume {session}`, transcripts folder + file) finds the last session's transcript, `claude --resume <id>` continues the conversation. A resume that never reached `session-start` is followed by a clean session. A session that vanishes while the daemon runs is auto-resumed at most `AUTO_RESUMES` (2) times per hour, then stays `error`.
- Commit identity (`gitUserName`/`gitUserEmail`, live): written to the managed gitconfig as `[user]`; `gitIdentities` (`scope` = `host[/owner]`) become `includeIf "hasconfig:remote.*.url:…"` blocks (HTTPS, scp-like and ssh:// patterns, git ≥ 2.36) pointing at `identities/N.gitconfig` next to it, so the identity follows the remote, not the path. Matching is case-sensitive, as git does it. Credentials are still one per host: a second account on the same host needs its own token handling (not done).
- Commit gates: on approval the actor itself runs `Git::commit_paths` (`git add --all -- files` then `git commit --only -m message -- files`, hooks run, 300 s timeout, inline in the actor: a deliberate exception to "slow work returns as WorkDone" because approve answers the UI with the result). The message is `Commit.message` (the agent's `--message`, else the subject) or the user's edit (`approve` body `message`). Success: commit `done` + sha (a later `commit done` with the same sha is a no-op). Failure: git's output in `.xherd/commit-error.txt`, status stays `approved`, and `/xherd:commit C01` has the agent fix and commit.
- `verify:` must be one runnable shell command. `tasks sync` (and `task done`) check it with `sh -n` and refuse `verify_invalid` before the tasks are approved (editing `tasks.md` after approval re-opens the gate); exit 126/127 at run time gets a hint in `verify_failed`. FORMAT.md and the tasks prompt say so.
- Tests never call the real `gh`: set `pluginSettings.github.gh` in `config.json` to a fake script (see `fake_gh` in `crates/xherd-daemon/tests/xap.rs`). The branch looked up is the agent name.
